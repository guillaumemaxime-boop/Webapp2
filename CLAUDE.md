## Spec Kit Workflow

Specification-driven development is the source of truth here. Follow this order for any new feature:

1. **Constitution** — `.specify/memory/constitution.md` defines non-negotiable principles (Spec-First, Plan-Before-Code, Test-First, Small Reversible Changes, Observability). Read this before planning anything.
2. **Spec** — `specs/NNN-slug/spec.md` captures WHAT and WHY (user scenarios, functional requirements, key entities). No tech details.
3. **Plan** — `specs/NNN-slug/plan.md` captures HOW (technical context, constitution check, project structure, phased approach). The `/plan` flow stops at Phase 2 (task-planning *description* only).
4. **Tasks** — `specs/NNN-slug/tasks.md` is generated from the plan's Phase 1 artefacts (`research.md`, `data-model.md`, `contracts/`, `quickstart.md`). Generated by `/tasks`, never by `/plan`.

The first feature scaffold lives at `specs/001-webapp2/`.
